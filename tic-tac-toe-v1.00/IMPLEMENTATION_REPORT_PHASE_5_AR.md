# تقرير تنفيذ المرحلة الخامسة — Tic-Tac-Toe Ultimate

**التاريخ:** 24 أكتوبر 2026  
**الحالة:** `PARTIALLY VERIFIED` — التحقق جزئي، مع مانع إصدار واضح متعلق بملف القفل واعتماديات npm.

## 1. الملخص التنفيذي

بدأت المرحلة الخامسة من نسخة المرحلة الرابعة. جرى تحسين بوابة التحقق حتى تميّز بين فحوص الموقع التي لا تحتاج إلى اعتماديات، وفحوص التطبيق الكامل التي تتطلب تثبيتًا قابلًا لإعادة الإنتاج. أُضيف فاحص مستقل لملف `package-lock.json` واختبارات رجعية له، وتم تحويل سير عمل GitHub Actions إلى تثبيت نظيف `npm ci` مع وظيفة مستقلة للفحوص الساكنة. تم إصلاح فاحص الموقع ليتحقق من استدعاء سكربت تدقيق الاعتماديات من `package.json` بدل افتراض وجود الأمر الخام داخل YAML.

تعذّر إنشاء `package-lock.json` في هذه الجلسة لأن DNS لا يستطيع حل `registry.npmjs.org`. لم يُنشأ ملف قفل تخميني أو غير صالح. لذلك يرفض فاحص القفل البناء الكامل صراحةً إلى حين أن ينشئه أحد في بيئة متصلة ويراجعه ويلتزم به في المستودع.

## 2. التغييرات المنفذة

### `scripts/check-lockfile.mjs` — جديد

- يتحقق من وجود `package.json` و`package-lock.json`.
- يشترط lockfile v3، ويتحقق من تطابق اسم المشروع وإصداره والأقسام المباشرة للاعتماديات بين بيان المشروع ومدخل الجذر في ملف القفل.
- يتأكد من وجود مدخل لكل اعتماد مباشر في `packages`.
- يقدم تعليمات صريحة لاستعادة ملف القفل عند غيابه.
- يترك التحقق الكامل من شجرة التبعيات وتكاملها لأمر `npm ci`؛ هذا الفاحص ليس بديلًا عن التثبيت النظيف.

### `scripts/test-lockfile.mjs` — جديد

اختبارات مستقلة دون اعتماديات خارجية تغطي ثلاثة سيناريوهات: ملف قفل سليم، ملف مفقود، وعدم تطابق متطلبات الاعتماديات.

### `package.json`

- أضيف `check:lockfile`.
- أضيف `test:lockfile`.
- أصبح `verify` يشترط وجود ملف قفل متوافق قبل اختبارات التطبيق والبناء، منعًا لادعاء أن بيئة غير قابلة لإعادة الإنتاج اجتازت التحقق.

### `.github/workflows/ci.yml`

- قُسم سير CI إلى `static-site-checks` و`full-verification`.
- فحوص الموقع واللغة واختبارات فاحص القفل المستقلة لا تعتمد على تثبيت React.
- البوابة الكاملة تشترط فاحص القفل، ثم تستخدم `npm ci --no-audit --no-fund` وتنفذ تدقيق الاعتماديات والتحقق الكامل.
- أضيفت صلاحيات `contents: read` فقط، وتعطيل حفظ بيانات الاعتماد بعد checkout، وحد زمني للمهام، وإلغاء التشغيل الأقدم على نفس المرجع.
- اختيرت إصدارات GitHub Actions الحالية `checkout@v7` و`setup-node@v7` وفق الوثائق الرسمية المتاحة وقت المراجعة.

### `scripts/check-site.mjs`

أُصلح التحقق من CI ليعتمد على `npm run audit:deps` الذي يعرفه المشروع، ويتأكد من أن بوابة CI تتضمن فحص ملف القفل والتثبيت بـ `npm ci`.

### التوثيق

- حُدّث `README.md` بتعليمات bootstrap مرة واحدة لملف القفل، ثم استخدام `npm ci` بعد الالتزام به.
- حُدّث `SITE_LAUNCH_CHECKLIST.md` لإظهار أن غياب ملف القفل مانع إصدار لا خطوة اختيارية.
- أُضيف هذا التقرير، وحُدّث `VERIFICATION.md` وفق نتائج المرحلة الحالية.

## 4. سبب عائق التثبيت

تم فحص سجل npm بالإعداد الحالي `https://registry.npmjs.org/`. لم يتمكن DNS داخل بيئة التنفيذ من حل اسم المضيف، وأعاد `curl` الخطأ `Could not resolve host: registry.npmjs.org`. انتهى تثبيت npm بمهلة، ولم ينتج عنه ملف قفل صالح. بقي مجلد `node_modules` المؤقت يحتوي فقط على ملفات TypeScript build-info وأزيل قبل إنشاء الأرشيف؛ لم تُضمّن اعتماديات جزئية.

لا يوجد حل سليم لإنشاء lockfile حقيقي دون معلومات الحزم المحلولة وتكاملاتها. لذلك تُرك الملف غير موجود بدل اختلاق بيانات تثبيت. توضح وثائق npm الرسمية أن `npm ci` يتطلب ملف قفل موجودًا ومتوافقًا مع `package.json`: https://docs.npmjs.com/cli/commands/npm-ci/.

## 5. مراجعة أمنية ذات صلة

بقي Vite مثبتًا على `6.4.5`. النشرة الأمنية الرسمية GHSA-8g5g-mxqh-grgj تسجل أن `6.4.4` هو الإصدار المتأثر وأن `6.4.5` هو الإصدار المصحح لهذه المشكلة المحددة: https://github.com/vitejs/vite/security/advisories/GHSA-8g5g-mxqh-grgj. لكن تدقيق شجرة الاعتماديات الفعلية لم يُشغّل بسبب غياب lockfile وانقطاع سجل npm؛ لذلك لا يُدّعى أن الشجرة كاملة خالية من الثغرات.

## 6. الخطوة المطلوبة لإغلاق مانع الإصدار

في بيئة متصلة بسجل npm، من جذر المشروع:

```bash
npm install --no-audit --no-fund
npm run check:lockfile
npm ci --no-audit --no-fund
npm run audit:deps
npm run verify
npm run preview
```

راجع `package-lock.json` الناتج والتزم به في المستودع. بعد ذلك يجب أن تجتاز مهمة `full-verification` في GitHub Actions. عند نجاح البناء فقط، نفّذ اختبارات متصفح فعلية ضد تطبيق React المبني واختبر العربية RTL والإنجليزية LTR والأنماط والأوضاع والبيانات المحفوظة.
