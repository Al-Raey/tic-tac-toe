# دليل نشر tic-tac-toe v1.00

## 1. المتطلبات قبل النشر

1. اختر مستضيفًا ثابتًا معتمدًا فعليًا وأنشئ المشروع/المستودع الخاص به. لا توجد وجهة استضافة أو نطاق مُهيأ داخل هذه الحزمة.
2. على جهاز أو Runner متصل بسجل npm، شغّل سير **Bootstrap and verify tic-tac-toe lockfile** في GitHub Actions، ثم نزّل أثر `ttu-package-lock` وراجع الملف الناتج والتزم بـ `package-lock.json` في المستودع.
3. تأكد من نجاح سير `Verify tic-tac-toe v1.00`.
4. شغّل **Build tic-tac-toe v1.00 release artifact**، الذي يثبت الاعتماديات عبر `npm ci`، ويدققها، ويشغّل `npm run verify:release`، ثم يرفع ناتج البناء كأثر `tic-tac-toe-v1.00-dist`.
5. نزّل أثر `dist/` وارفع محتوياته إلى جذر موقع الاستضافة الثابتة. هذه الخطوة تتطلب حساب الاستضافة والصلاحيات التي لم تُوفر ضمن بيئة العمل.

## 2. إعدادات بناء متوقعة

- إصدار Node.js: 22.x (ويجب أن يحقق `engines` في `package.json`).
- تثبيت الاعتماديات: `npm ci --no-audit --no-fund`.
- التحقق: `npm run verify:release`.
- مجلد النشر: `dist/`.
- الاسم الظاهر: `tic-tac-toe v1.00`.
- الإعلانات: متوقفة ما لم يُكمل مالك الموقع التهيئة والموافقة المطلوبة.

## 3. فحص بعد النشر

اختبر الرابط العام الفعلي من متصفح مستقل: الصفحة الرئيسية، مباراة ضد الذكاء الاصطناعي، إعادة اللعب، العربية/RTL، الصفحات العامة الخمس، تحميل CSS والأيقونة والـ manifest، وعدم ظهور أخطاء حرجة. لا تضف canonical URL أو sitemap يحتوي على نطاق إلا بعد معرفة النطاق الإنتاجي النهائي.

## 4. إجراءات مالك الموقع

- اختيار وتكوين نطاق أو عنوان استضافة فعلي.
- إضافة قناة تواصل حقيقية تتم متابعتها في `public/contact.html`.
- مراجعة سياسة الخصوصية والشروط وفق بيانات المشغّل والاختصاص القانوني.
- استكمال ملف قفل الاعتماديات والتأكد من نجاح جميع البوابات.
- لا يُعلن عن نشر ناجح إلا بعد التحقق من URL مباشر واختباره.
